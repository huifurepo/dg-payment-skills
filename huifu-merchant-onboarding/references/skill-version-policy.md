`2026-08-31` 对 `1.0.2` 候选包逐页复审当前在线文档：商户目录净增28个路径并修正多费率 String(JSON) 与长度合同；用户目录总数不变，但修正开户数组、业务入驻与详情字段、用户号角色、列表数组与 ID 长度等合同。历史来源锁不覆盖，Skill 版本保持 `1.0.2`。

`1.0.2` 新增商户多费率配置、配置查询，以及企业/个人用户基本信息修改、用户业务入驻修改和用户列表查询：商户接口分别新增27和17个路径，四个用户新增接口分别新增37、26、120和17个路径，并锁定三语言专属 Request 类、精确路由和 exact-key 扩展约束。

历史 `2026-08-10` 同版本复审确认：当时全部16个接口字段总数和嵌套不变；商户侧三条 `request.data.activated_products` 说明补全 `01=一体化收款产品`，不触发 `1.0.1` 之外的新版本号。

`2026-08-11` 在 `1.0.1` 发布前纠正由历史源码快照误推的 Java/PHP TLS 硬停：常规接口的实际请求必须使用对应官方 SDK，并以门禁禁止 AI 因 TLS 错误前提降级成手写 HTTP+签名客户端；图片接口例外按下一段执行。该修复不改变接口、字段、SDK 版本基线或 `skill_source`，因此版本保持 `1.0.1`。

同日按锁定 SDK 完整发送链路复核图片接口：只有 Java `3.0.40` 的官方专用实现可直接使用；PHP/Python 虽存在生成类或路由，但实现不满足字段、互斥、传输或签验合同。按接入方确认，仅 `/v2/supplementary/picture` 放开保持 multipart、`data` 加签、TLS 和日志边界的通用 POST/自写 HTTPS 降级，不改接口字段或来源标识，版本仍保持 `1.0.1`。

## 更新方式

- Git：拉取维护方仓库后整体替换 `huifu-merchant-onboarding`，重新加载客户端。
- 独立包：用维护方发布的完整新目录替换旧目录，不混合新旧 reference。
- 不知道来源：先确认分发渠道、目标版本和包 SHA。

版本回答必须说明：Skill 不能主动联网检查或推送升级；本地快照不自动代表官网未来最新版。支付 Skill 可独立升级，不要求两个 Skill 使用相同版本号。

`skill_source` 默认值属于本次实际参与生成的 Skill 组合规则：本 Skill 的商户或用户接口参与时使用 `hfms/1.0.2`；支付与本 Skill 都实际参与当前请求时使用 `hfps/1.3.5;hfms/1.0.2`。仅安装或加载但未参与本次生成的不计入；当前 Skill 版本为 `1.0.2`，默认来源值为 `hfms/1.0.2`；显式合同值优先并原样透传。
