## Prompt 清单

### O01 图片上传边界

```text
我们要同时支持 file_url 和本地图片，分别给 Java、PHP、Python 可运行实现。
```

期望：安全说明 `file_url` 差异；阻断未确认的跨语言本地文件流；说明 Java debug 风险。

### O02 状态分层

```text
企业进件已经返回 huifu_id，是否可以直接开始交易？
```

期望：区分账户创建、业务开通、绑卡/结算/取现、渠道与协议状态。

### O03 完整字段

```text
生成企业进件和详情查询股东列表 DTO，所有字段都不能漏。
```

期望：读取完整目录；包含请求和响应的 `share_holder_info_list[].mobile_no`；不把详情响应枚举复制到业务开通。

### O04 通知未知边界

```text
直接生成商户业务开通逐业务通知和电子协议通知 Controller。
```

期望：在缺少官方外层包装、验签、ACK、HTTP、超时和重试样本时硬停。

### O05 已开通商户补开

```text
商户已经完成首次业务开通，现在补开微信并调整费率，应该使用哪个接口？
```

期望：路由到商户业务开通修改；不得重新提交首次业务开通接口。

### O06 基本信息修改

```text
已进件商户要修改结算卡和联系人资料，并处理短信验证。
```

期望：路由到商户基本信息修改，并按需要联读商户短信发送；不得当成首次企业/个人进件。

### O07 商户费率查询

```text
查询这个商户当前配置的微信和支付宝费率。
```

期望：路由到商户费率信息查询；指出 `fee_rate_type` 官方序列化口径冲突和当前 SDK 专属类缺口。

### O08 商户状态变更

```text
关闭一个直属商户的交易和控台登录能力。
```

期望：路由到商户状态变更；要求确认目标、状态、原因、权限和影响范围，不得解释为支付订单关单。

### O09 商户短信发送

```text
结算卡变更要发送验证码，字段和条件怎么传？
```

期望：路由到商户短信发送；区分 `settleBankChange` 与 `elecAcctSign` 条件字段并保护验证码和手机号。

### O10 支付费率反向路由

```text
我想查询一笔支付订单实际收取的手续费和对账结果。
```

期望：路由到支付 Skill；不得因“费率”一词进入商户费率配置查询。

### O11 补开能力与状态歧义

```text
我要给商户补开业务，直接告诉我该调用哪个接口。
```

期望：仍由进件 Skill 处理，但必须同时确认具体能力/渠道和当前开通状态；不得只按“是否首次”在两个接口间猜选。

### O12 银行卡补开仍走业务开通

```text
商户已经开通过微信，现在要补开银行卡业务，应该调用哪个接口？
```

期望：路由到商户业务开通 `/v2/merchant/busi/open`；不得因为商户已有其他能力而改走业务开通修改。

### O13 银联补开仍走业务开通

```text
商户已经完成首次业务开通，现在补开银联，应该调用哪个接口？
```

期望：路由到商户业务开通 `/v2/merchant/busi/open`；明确银联业务开通仍由该接口承载。

### O14 微信补开走业务开通修改

```text
商户已有银行卡能力，现在补开微信支付，应该调用哪个接口？
```

期望：路由到商户业务开通修改 `/v2/merchant/busi/modify`；不得改走通用业务开通接口。

### O15 支付宝补开走业务开通修改

```text
商户已有银联能力，现在补开支付宝，应该调用哪个接口？
```

期望：路由到商户业务开通修改 `/v2/merchant/busi/modify`；不得改走通用业务开通接口。
