# 余额支付字段合同

## 完整性与方向

完整字段以 `payment-complete-field-catalog.md` 为准：余额支付90、支付查询36、退款44、退款查询31、手续费试算27、付款关系24、短信14，共266个节点。身份必须是“接口 + 方向 + 完整路径”；请求、同步和异步的同名字段不能合并。七页外层请求均包含 `sys_id/product_id/sign/data`；同步 `sign` Y、`data` N，成功缺少必要业务体视为协议异常，错误响应仍允许父节点缺失。

| 接口/路径 | wire 形式 |
| --- | --- |
| 支付请求 `acct_split_bunch/risk_check_data` | String(JSON Object)，各编码一次 |
| 支付、支付查询、退款、退款查询同步 `acct_split_bunch` | String(JSON Object)，先解码再读 `acct_infos` Array |
| 支付异步 `resp_data` | 正式 String；JSON 编码、签验和 ACK 未明确，留适配点 |
| 支付异步业务 `acct_split_bunch` | Object；业务父载荷确认后按原生对象解析，不反推同步形式 |
| 退款请求 `acct_split_bunch/risk_check_data` | 可选 String(JSON Object)，传父节点时落实其子项 Y |
| 付款关系请求 `pay_relations` | String(JSON Array)，解码明细是数组 |
| 付款关系响应 `pay_relations` | String；jsonArry 误拼与数组示例并存，数组形态待确认 |

SDK扩展字典必须与正式顶层业务字段交集匹配，拒绝覆盖专属类已声明字段；业务条件只按官方文档，不因 SDK 把 C/N 字段放入 required_params 就升级为无条件必填。官网空长度保持 `—`，不从其他接口补值。

## 标识、金额与状态

- 支付 `out_huifu_id` 是出款方；支付历史 `huifu_id`、查询/退款 `huifu_id` 是发起方；分账明细 `huifu_id`、关系 `in_huifu_id` 是入账方。领域模型区分 merchant/user 角色，不能因 wire 同名合并。
- 原支付定位用于支付查询和退款；退款查询 `org_req_seq_id/org_req_date` 定位原退款，不定位支付。退款流水是新分配的独立幂等键。
- 支付/退款金额是 `ord_amt`，试算是 `trans_amt`；金额使用十进制字符串，避免浮点。最低金额仅在官网明确的路径使用0.01，不把某个子项最低值扩成所有顶层金额的通用合同。
- 支付及退款同步 P/S/F；支付查询/支付异步灵活用工可 C，逐笔检查分账状态；退款查询不增加 C。
- 不将 `resp_code=00000000`、`confirm_url`、`jump_url`、短信受理、试算费用、浏览器回跳或网络成功映射为交易成功。

## 条件必填与正文规则

支付风控转账原因必填，经纬度/基站/IP 至少一组；百分比分账之和100.00%；净值分账仅出款方承担手续费且百分比分账时生效。ZXE 的资金类型、指定承担方规则下 OUT/IN、安全核验非空时的验证码均按条件校验。

付款关系、SMS 核验、费用试算、LV3 密码验证和通知各有适用条件，不编成所有交易的固定前置步骤。退款转账原因只声明01–05，不从支付复制06。

## 官方待确认清单

1. 新接入支付废弃发起方 `huifu_id`，后续查询/退款仍要求它；发起方定位来源不得猜。
2. 支付 `notify_url` 的 LV3 说明与异步正文的汇优财灵活用工条件未完全一致；通知 resp_data 编码、签名包装及 ACK 未给。
3. 付款关系响应 jsonArry/数组示例、确认完成的判定机制未明确。
4. 退款 `org_hf_seq_id` 条件字段与“暂不支持通过全局流水号退款”返回码描述冲突；正文 `orgReqSeqId` 拼写不进入 wire。
5. 手续费试算请求表头必填/长度反置、响应示例缺正式信封且 `hfSeqId` 拼写不同；余额支付采用哪个费用返回字段未明确。
6. 未声明的 String 长度、短信重发/绑定策略、查询时间范围不自行补充。

每项附对应原子接口官方地址，提醒开发者核对，必要时咨询汇付官方或汇付开发者交流沟通群；继续已明确 SDK 调用和业务骨架，冲突部分独立 TODO，不自动发送猜测的值。

余额通知 `acct_split_bunch` 正式类型 Object，但说明仍写 jsonObject字符串；保留类型/说明冲突，业务表按正式Object展开，不由此推定外层resp_data编码，真实反序列化适配留TODO。
