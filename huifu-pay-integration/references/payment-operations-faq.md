# 支付配置与运营 FAQ

## 通道和路由

- “接口权限认证失败”或 `20003` 时检查目标环境、接口路径、请求头、`sys_id` 和当前接口授权，不通过替换业务字段碰运气。
- “数据权限认证失败”时检查 `product_id`、`sys_id`、交易 `huifu_id`、`upper_huifu_id`、请求头和上下级归属关系，不借用其他商户或产品号，也不在测试、生产或不同服务商层级之间混用同一组标识。
- 接口、产品或上级链路权限开通若伴随密钥或环境配置变更，必须同步核对生产配置和密钥管理，不能由 Skill 自动替换。
- “该路由下未配置可用通道”时检查渠道业务是否开通、线上/线下场景、`pay_channel`、`pay_scene` 和 `channel_no`。
- 不指定渠道时不要传空字符串 `channel_no`。
- 账户或渠道尚未准备完成时，将进件实施交给 `$huifu-merchant-onboarding`；本页只判断支付前置是否满足。

## appid、openid 和授权目录

- `sub_mch_id` 与 `sub_appid` 不匹配：检查 appid 绑定、配置首尾空格和商户渠道关系。
- `sub_openid` 必须来自同一 `sub_appid` 的授权流程，不能跨公众号或小程序复用。
- URL 未注册或 `redirect_uri` 域名不一致时，核对授权目录、网页授权域名、实际回跳地址和配置生效延迟。

## Webhook

- 控台 Webhook 的 `sign` 常位于 URL query；验签使用原始 body 和 endpoint key。
- 服务商接收下属机构事件时检查“统一接收下属机构事件”配置。
- 控台 Webhook 与接口 `notify_url` 不能共用验签和 ACK 规则。

## 退款、对账和资金运营

- 退款处理中时使用退款查询等待终态，不换流水并发重试。
- 延时分账退款要区分未确认部分和已确认部分：未确认部分可按交易退款处理；已确认部分先走确认退款或资金回退，再退回原付款方。
- 对账文件未生成时检查功能、跑批日期和任务状态。
- 取现额度、手续费发票、税务、费率和资金争议只整理材料转人工，不写支付接口代码解决。

## 边界

不输出通道准入、费率、风控、审核、取现额度或发票结果的最终结论。涉及企业/个人材料、业务开通、详情或申请状态时使用 `$huifu-merchant-onboarding`。
